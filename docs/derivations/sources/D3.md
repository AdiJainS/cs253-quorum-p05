# D3 Architect — range gcd with point assignments

**Author:** Anushri Maheshwari, roll number 250041005, D3 Architect.

**PDF source:** `D3-latex/main.tex` is the canonical source for the two-page PDF.

**Status:** Architect derivation; see INTERFACE.md for the application contract. The sensor array contains nonnegative integers. Queries use zero-based half-open intervals [l,r); assignments replace a value, including decreases and zero. Define gcd(0,0)=0. Let V be the largest value allowed over the entire replay, including assignments. For uniform edge-case bounds write H=1+log₂(n+1) and L=1+log₂(V+1).

## 1. Algebraic contract

Work on the nonnegative integers. Use the following characterization of gcd: for every positive integer d,

    d divides gcd(a,b) iff d divides a and d divides b.

For positive inputs this is the standard greatest-common-divisor property; when one input is zero it gives gcd(a,0)=a, and when both are zero we use the stated convention. Nonnegative integers are uniquely determined by their positive divisors: for positive numbers mutual divisibility gives equality; zero alone has every positive integer as a divisor.

**Commutativity.** The characterization is unchanged when a and b are exchanged, so gcd(a,b)=gcd(b,a).

**Associativity.** For every positive d,

    d | gcd(gcd(a,b),c)
      iff d | a and d | b and d | c
      iff d | gcd(a,gcd(b,c)).

Uniqueness gives gcd(gcd(a,b),c)=gcd(a,gcd(b,c)), including all zero cases.

**Identity.** Every positive d divides zero. Thus gcd(a,0) and a have exactly the same positive divisors, giving gcd(a,0)=a; commutativity gives gcd(0,a)=a. Therefore (nonnegative integers, gcd, 0) is a commutative monoid.

## 2. Segment-tree correctness

Each leaf stores its array value; padding leaves store 0. Each internal node stores the gcd of its children. Induction on height, using associativity and identity, proves that every node stores the gcd of its covered leaves.

The iterative query strips the odd left boundary node and odd right boundary node, then moves both boundaries to their parents. The stripped blocks are disjoint, and together with the unprocessed middle they partition the original interval. At termination the selected blocks cover exactly [l,r). Folding their values gives its gcd by associativity; commutativity permits the implementation's mixed left/right selection order and single accumulator. A generic noncommutative monoid would need ordered left and right accumulators. An empty query selects nothing and returns 0.

An assignment changes one leaf and recomputes all its ancestors, bottom to top. Nodes outside that path cover unchanged values; nodes on it regain the invariant from their children. This proves correctness for increases, decreases, and zeros without any monotonicity assumption or inverse.

Prefix gcds cannot be subtracted or otherwise inverted: arrays [6,10] and [6,14] have the same prefix gcds [6,2], but their second-element ranges have gcds 10 and 14. Thus even knowing both relevant prefix gcds cannot determine an arbitrary range gcd.

## 3. Straightforward time bound

A balanced tree has O(H) levels. At most two blocks are selected per level, so a query performs k=O(H) merges plus O(H) index work. Euclid uses O(L) remainder steps per merge, giving O(HL), conventionally O(log n log V) for n,V≥2. A point assignment has the same straightforward bound. Storage is O(n); construction performs O(n) gcd calls and has the safe bound O(nL).

## 4. Sharper query bound: Euclidean telescoping

Here we count arithmetic operations in the model specified below, using the explicit remainder-based Euclid routine in the implementation.

**Euclidean lemma.** For positive a,b and d=gcd(a,b), Euclid costs

    O(1 + log₂(a/d))

remainder steps, even when b is larger than a.

Proof: divide both inputs and every nonzero remainder by d. Scaling preserves the quotient sequence and number of remainder steps. After at most one initial division, the smaller positive operand is at most a/d. For two consecutive positive operands x≥y, let r=x mod y. If r≤y/2, the smaller operand has already halved; if r>y/2, the next remainder is y mod r=y-r<y/2. Thus it halves within at most two divisions until it reaches 1; only a constant number of termination steps remain. This proves the lemma. For b=0 the call is constant time and leaves a unchanged.

Now let x₁,…,xₖ be the selected node gcds in the implementation's actual order. Start with g₀=0 and set gᵢ=gcd(gᵢ₋₁,xᵢ). Calls while the accumulator is zero cost O(1): gcd(0,x) takes at most one remainder and adopts x. If it never becomes positive, total work is O(k).

Otherwise let gⱼ be its first positive value. It is at most V. For i>j, gᵢ is a positive divisor of gᵢ₋₁. The lemma, including the constant-time zero-operand case, bounds call i by

    O(1 + log₂(gᵢ₋₁/gᵢ)).

Consequently the total number of remainder steps is

    O(k + Σᵢ₌ⱼ₊₁…ₖ log₂(gᵢ₋₁/gᵢ))
      = O(k + log₂(gⱼ/gₖ))
      ⊆ O(k + log₂ V).

The empty sum covers a single positive merge. Adding traversal gives O(H+L), conventionally **O(log n + log V)**. The lemma is essential: simply counting strict decreases does not account for all divisions inside each gcd call. This is an upper bound, not a claim that every query requires that much work or that both terms have matching lower bounds in every parameter regime.

## 5. Computational model and limits

- The additive bound is a bound on remainder steps plus tree operations. To call it elapsed-time complexity, assume a word RAM with word width w sufficient for both values and tree indices, and constant-time comparison, indexing, and unsigned division/remainder on one word. In particular w must accommodate log₂(V+1) and log₂(n+1). Arbitrary-precision arithmetic does not satisfy this assumption.
- For the supplied unsigned long long code, values fit in unsigned long long (at least 64 bits; typically 64 bits). With fixed-width machine operations treated as constant time, log V is bounded by a constant and queries are O(H). Physical division latency is hardware-dependent; this theorem does not predict benchmark timings.
- For arbitrary-precision b-bit inputs, b=max(1,⌈log₂(V+1)⌉), the same proof bounds the number of Euclidean divisions by O(H+b). It does not make each division constant time. For example, charging O(b²) bit operations per schoolbook remainder gives the conservative arithmetic bound O((H+b)b²), plus traversal/index costs and representation/storage costs. This is deliberately not asserted to be an optimal bit bound.
- The implementation uses an explicit Euclidean loop so the division analysis matches the algorithm. A standard-library gcd may use another algorithm; correctness alone does not transfer this exact remainder-count proof to that implementation.
- The displayed telescoping argument applies to a query's running gcd. Updates recompute sibling pairs, so we retain the safe O(HL) update bound here; no sharper update claim is needed.

The standard halving argument and background on Euclid are described in [Stanford's Euclid notes](https://crypto.stanford.edu/pbc/notes/numbertheory/euclid.html). The query-specific ratio lemma and telescope above are supplied as a self-contained derivation. For arithmetic-versus-bit complexity background see [Victor Shoup, A Computational Introduction to Number Theory and Algebra](https://shoup.net/ntb/ntb-v2_2.pdf).


## Application of this proof to this version

The generic query uses separate left and right accumulators. Each accumulator receives O(log(n+1)) node gcds and satisfies the same lemma independently, even though its calls are interleaved with the other chain. The final merge costs O(1+log(V+1)). Adding the two chains and final merge still gives O(log(n+1)+log(V+1)). Operation counters include the final merge and all zero operands. They do not turn the upper bound into a tight lower bound.
